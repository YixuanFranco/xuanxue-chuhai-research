# Ask Me Anything · 假设与一手素材区

> **这里放的是「还没验证的东西」**：群内答疑、临时冒出来的假设、对某个判断的反例、别人问出来的好问题、自己测出来的零散数字。
> 跟 [`玄学出海/`](../玄学出海/README.md) 的区别：那边是**带证据、带信度、一轮一轮做出来的调研结论**；这边是**原始素材**。
> **默认规则：本文件夹里的一切都先当假设，不要当结论引用。**

---

## 一、这里放什么

| 放 | 不放 |
| --- | --- |
| 群内 AMA 的转写整理 | 已经写进 `玄学出海/` 的正式报告（别复制两份，会慢慢对不上） |
| 各种假设：能成立 / 不成立 / 还没测的 | 没有来源的「听说」当事实 |
| 一手实测的零散数字（退货率、成本、开店规则…） | 个人隐私、群友昵称、内部文档链接、活动二维码 |
| 别人提出的好问题，尤其是把前提问歪的那种 | 收费课程内容、方法论原文 |

一次转写一份文件，别往一份里无限追加；同一话题聊了第二轮就开第二份，文件名上带日期。

## 二、文件怎么起名

```
2026-11-10-玄学电商退货率与东南亚店群.md
2026-11-12-关于退货率是不是期待差的一轮追问.md
```

**日期开头 + 有语义的名字**。不用 `01-`、`R1-` 这类轮次编号——这里不按轮次走，编号一编就得维护顺序，反而累。也不用字母数字代号指代东西，写中文全名，读者不用翻来翻去。

每份文件开头放一段 YAML 头：

```yaml
---
title: 这份文件叫什么
date: 2026-11-10
status: 一手素材 / 未验证 / 已并入正式调研 / 已证伪
method: 群内答疑转写 / 自测记录 / 追问
permission_scope: 公开
---
```

`status` 会变：一份假设后来被《玄学出海》的某一轮证实或证伪了，回来把这里的状态改掉，并在文末写一行「并入 / 证伪于哪份文件」。**这是本文件夹唯一需要回头维护的动作。**

## 三、三条硬规矩（沿用全库，但这里更严）

1. **带来源**：每个数字写清是「谁在什么时候、什么场合说的」或「自己怎么测的」。
2. **标信度**：✅ 可核实 · 🟡 单一来源 · ⚠️ 当事人自述 / 营销数字 · ❓ 未查到。**本文件夹默认全是 ⚠️**——群聊里说出来的数字没有第三方核验，哪怕是运营者自己测的。
3. **判断和证据分开**：标「判断」或「推断」的句子就是没有直接证据，别混在事实里写。
4. **不编**：查不到写「未查到」；忘了就说忘了。

## 四、脱敏约定（开源版口径）

仓库是公开的。本文件夹沿用 [`玄学出海/README.md`](../玄学出海/README.md) 里「开源版去掉了什么」的同一口径，转写时**不收录**：

- 群友昵称、头像、贴纸、@ 提示 → 统一写成「提问」；
- 内部文档 / 飞书 / 网盘链接、活动二维码与编号、报名信息；
- 可识别的具体业务主体（店铺、公司、律所、货盘、合作方）→ 改成中性称呼，如「国内高客单玄学直播间（主体已脱敏）」「面向美国的技术服务」；
- 规避平台审核的具体话术黑话（只保留「某类表述不能说」这个合规结论）。

**原始完整版不进公开仓库**，由 Yixuan 自己留档。要在这里补原文，先想一遍它会不会被搜索引擎抓走。
